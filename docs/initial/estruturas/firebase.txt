COSMAKER OS — ESTRUTURA FIREBASE
================================

OBJETIVO
--------
Estrutura preparada para funcionar inicialmente com um único ateliê, mas já modelada como multi-tenant/SaaS.
Cada ateliê é uma unidade isolada de negócio e concentra seus próprios clientes, pedidos, orçamentos, agenda, produção, financeiro e arquivos.

STACK FIREBASE
--------------
- Firebase Authentication
- Cloud Firestore
- Firebase Storage
- Cloud Functions
- Firebase Hosting (opcional, dependendo do deploy do frontend)
- Firebase Cloud Messaging (opcional para notificações push)

SEGURANÇA
---------
1. Cliente só acessa dados vinculados ao próprio UID/clientId.
2. Membro do ateliê só acessa dados do atelierId ao qual pertence.
3. Financeiro deve depender de permissão explícita.
4. Alterações críticas de valor, status de pagamento, reembolso e conclusão não devem confiar no cliente web.
5. Webhooks de pagamento devem validar assinatura/origem.
6. Uploads precisam validar tamanho, MIME type e caminho permitido.
7. Não permitir leitura pública de documentos internos.
8. Portfólio público deve usar coleção/documentos próprios ou regras explícitas.
9. Usar audit log para ações críticas.
10. Exclusão de documento pai não remove subcoleções automaticamente; usar rotina backend para exclusões completas.

ÍNDICES PROVÁVEIS
-----------------
- orders: status + expectedDeliveryDate
- orders: clientId + createdAt
- quoteRequests: status + createdAt
- quotes: status + createdAt
- transactions: type + date
- notifications: userId + read + createdAt
- productionSlots: year + month
- portfolio: public + featured
- conversations: clientId + lastMessageAt

PRINCÍPIO
---------
O Firestore deve guardar estado e metadados; arquivos pesados ficam no Storage.
Documentos principais devem permanecer pequenos.
Históricos, mensagens, imagens e listas que crescem devem usar subcoleções.

COSMAKER OS — ESTRUTURA DO SISTEMA
==================================

VISÃO
-----
Sistema web para gestão completa de ateliês/cosmakers.
O produto combina:
- Site público/portfólio
- Captação de solicitações
- Orçamentos
- Pedidos
- Produção
- Agenda e capacidade
- Medidas
- Aprovações
- Pagamentos
- Financeiro
- Estoque
- Clientes/CRM
- Comunicação
- Entrega
- Relatórios
- Administração SaaS

STACK SUGERIDA
--------------
Frontend:
- Next.js
- React
- TypeScript
- Tailwind CSS
- shadcn/ui ou componentes próprios

Backend/Infra:
- Firebase Authentication
- Firestore
- Firebase Storage
- Cloud Functions
- Integração de pagamento
- Integração WhatsApp
- E-mail transacional

REGRAS IMPORTANTES
------------------
1. Pedido nasce de orçamento aprovado, salvo criação manual autorizada.
2. Valor aprovado deve ter snapshot e histórico.
3. Mudança posterior relevante gera change request ou nova versão de orçamento.
4. Medidas usadas em pedidos devem ser copiadas para snapshot.
5. Alterar ficha atual não altera pedido antigo.
6. Produção deve trabalhar com etapas configuráveis.
7. Etapas podem exigir aprovação do cliente.
8. Fotos de produção podem ser internas ou visíveis ao cliente.
9. Pagamento confirmado deve vir de webhook/backend ou ação administrativa protegida.
10. Agenda é baseada em capacidade real, não apenas calendário de compromissos.
11. Cada serviço pode consumir peso/horas de capacidade diferentes.
12. Sistema deve alertar risco de atraso.
13. Cliente não acessa dados de outros clientes.
14. Membro só acessa ateliê ao qual pertence.
15. Financeiro e configurações exigem permissões específicas.
16. Toda ação crítica deve poder gerar log.

AGENDA E CAPACIDADE
-------------------
A agenda deve combinar:
- Calendário
- Horas/pontos disponíveis
- Pedidos alocados
- Etapas agendadas
- Provas
- Reuniões
- Eventos
- Férias/bloqueios

Exemplo conceitual:
Capacidade outubro: 120h
Agendado: 82h
Disponível: 38h
Ocupação: 68%

O sistema deve sinalizar:
- Aberto
- Quase lotado
- Lotado
- Bloqueado

ESTOQUE
-------
Materiais devem permitir:
- Quantidade atual
- Unidade
- Estoque mínimo
- Custo médio
- Entrada
- Saída
- Ajuste
- Vínculo com pedido
- Vínculo com fornecedor

PORTFÓLIO
---------
Projeto concluído pode gerar item de portfólio.
Não publicar automaticamente sem autorização/configuração.

RESPONSIVIDADE
--------------
Desktop é prioridade para o painel do ateliê.
Mobile precisa funcionar bem para:
- Cliente acompanhar pedido
- Cliente aprovar etapa
- Cliente pagar
- Cliente enviar referência
- Cosmaker atualizar status/foto rapidamente

PADRÃO VISUAL
-------------
Referência criada nas telas iniciais:
- Fundo claro
- Roxo como cor principal
- Rosa/magenta como acento
- Cards arredondados
- Navegação lateral no painel
- Cards com status colorido
- Visual criativo sem perder aspecto profissional
